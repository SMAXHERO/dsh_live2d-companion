## 0. 结论先行（先看这三句）

1. **人设/设定这块你已经领先了，别推翻。** 你的 `persona/system-prompt.md`（63 行：身份 / 六条性格 / 说话规则 / 场景规则 / JSON 输出协议 / 防呆）比 11 个仓库里任何一个都细；`persona/persona.json` 的 appearance、emotionRules 也是它们在做的「角色卡」。要补的是**两样**：位置约束（硬规矩挪到 prompt 最末尾）和 AI 味黑名单。

## 1. 需要你先拍板的 6 个决策

每条都给了推荐值。你可以只回「全按推荐」，或改其中几条。

### D1 形态：独立网页 / DSH 插件 / 双形态
- **A 独立网页**（现状）：零依赖，双击 start.bat 就跑；但拿不到你在 DSH 里的工作状态。
- **B DSH 插件**：能直接吃 agent 事件，但依赖 DSH 插件机制，改动面大、发布形态也变。
- **C 双形态（推荐）**：网页保留；**只加一个状态读取器**去读 DSH 的会话文件（`~/.dsh/sessions/**/session.v4.jsonl.zstd`），读到什么就演什么。不注册插件、不改 DSH 配置，随时能关。
→ 推荐 **C**，放 P1 做。

### D2 Live2D：不换 / 伪 Live2D 增强 / 真 Cubism 迁移
- **不换**：0 成本。
- **伪 Live2D 增强（推荐）**：呼吸起伏、眨眼、视线跟随鼠标、说话时头身轻摆，全用 Canvas 变换 + 现有图集图层做。约 1 天，观感能到「像活的」的 70%。
- **真 Cubism**：3 个 vendor 文件 + 可用模型 + 44 表情参数手工映射 + 点击 alpha 命中；3~5 天，还会破坏现有 32 动作图集管线。
→ 推荐 **伪 Live2D 增强**；真 Cubism 等你哪天想换形象再说。

### D3 表情包：复用现有图集 / 独立贴纸包 / 两者都要
- **复用图集**：把现有 POSES 当「表情」发出去，零新素材，表达力有限。
- **独立贴纸包**：WebP 贴纸（10~40 张），能表达「收到 / 谢谢 / 好耶 / 晚安 / 奶茶」这类图集没有的语义。
- **两者都要（推荐）**：贴纸管「梗与情绪」，图集管「她在干什么」，互不冲突。
→ 推荐 **两者都要**；素材与许可见 §6.4。

### D4 记忆与好感：进不进 prompt
- 记忆：**进**，但只进「摘要段」（≤16000 字上限，四区裁剪），原文不进。
- 好感度：**只做代码侧硬约束**（决定主动搭话频率、贴纸概率、称呼、回复长度上限），**不写进提示词**。反证：whale-loli 把 17KB 好感度模块整套删掉——写在提示词里设 -100，她照样喊「主人」。
→ 推荐按这两条做。

### D5 语音：现在做 / 留到 P2
- 现在做：Edge-TTS 免费、无 GPU 可跑，但口型同步与打断又是一堆活。
- 留到 P2（推荐）：先把「说话内容 + 表情 + 贴纸」做扎实。
→ 推荐 **留到 P2**；本轮只预留 tts 配置项与「剥 emoji 再读」（whale-pet 的坑：带 ✨ 的台词永远匹配不上音色片段）。

### D6 角色数量：单角色 / 支持人设预设切换
- 单角色（现状）：维护成本最低，人设一致性最好。
- 多预设：参考 persona-select 的 sectionOrder 机制，能做「白天女儿 / 晚上女仆」切换。
→ 推荐 **单角色 + 把 persona 目录做成「换一套文件就是换一个人」**，UI 切换等真需要再说。

## 2. P0：先做这三件（约 1.5~2 天，收益最高、风险最低）

### P0-1 对话长度「双保险」+ 说话节奏

**现状问题**：长度只写在提示词里（system-prompt.md 的「一句 6~24 字，一到两句」）。模型偶尔一次吐 80 字，前端照单全收；流式还会边到边显示，长句把气泡撑爆。

**做法**：
1. `config.js` 增加 `reply` 段：
   - `maxChars: 40`（硬上限）、`softChars: 24`（软目标）、`maxSentences: 2`
   - `byMood`：excited / angry 放宽到 60，sad / hurt / bored 收到 20
   - `byScene`：`busy: 16`（用户很忙，一句话退场，对应人设里的「用户很忙：一句话就退场」）
2. **提示词动态插入**：不再写死「6~24 字」，改成按当前情绪 / 场景拼一句「这一轮：≤{n} 字，{k} 句以内」。
3. **代码侧硬截断**（dafeiyu `桌宠.py:8058` 的 `reply[:28] + "…"` 思路，但更礼貌）：
   - 流式 `onDelta` 累计超过 maxChars → 在最近的句末标点（。！？…）处切，追加「…」，停止追加
   - 超 2 句 → 拆成两个气泡（第二条延迟 700ms，参考 whale-loli「想补一句就分条发」）
4. **验收**：连发 20 轮，统计 say 长度 P50 ≤ 18 字、P95 ≤ 40 字、超 maxChars 轮次 = 0；气泡无一次溢出。

**参考**：`mdd111/deepseek-dafeiyu-pet:桌宠.py:8058`、`wxzjss/dsh-whale-loli:src/persona-v2-live.md`、`Andersen216:assets/pet.js:2544`。

### P0-2 表情包/贴纸系统（最大空白）

**目标**：她能在合适时机**发一张图**，而不是只能用文字和符号。

**四件套**（照 `FeWOO/DeepSeek-meme`，社区现成最完整的结构）：
1. **数据模型**：`assets/stickers/<pack>/manifest.json` + `*.webp`
   - sticker：`{id, name, meaning, tags[], mediaType, bytes, width, height, url}`
   - pack：`{id, name, description, order, bundled, stickers[]}`
   - 约束照抄：单张 ≤1MB、每包 ≤50 张、拒 SVG、读文件头嗅探真实格式（`index.js:35-140`）
2. **让模型「看得懂」**：meaning 必须写「什么时候用」（例：nice-work → 交付完成、测试通过时用），再用 catalogText() 压成 ≤120 行纯文本目录塞进 system prompt（`index.js:194`）——比塞 JSON 便宜，还能精确选 id。
3. **模型协议扩展**：现有输出 JSON 加一个字段
   `{"say":"...","mood":{...},"sticker":{"id":"nice-work"}}`，sticker 可为 null（大多数轮次都该是 null）。
   - system prompt 尾部加 180 字规矩（照 `index.js:1048` 的 section 写法）：何时主动发、何时闭嘴、每轮最多一张
   - 代码侧不信任模型：id 不在 catalog 就丢弃；连续 3 轮都发 → 强制降频
4. **前端**：气泡旁渲染 `<img>`（不是 emoji）；输入框旁加 🎨 面板可手动选发，按 pack 分组。

**触发策略（本地直连 API，不需要 DSH 那套掷骰注入）**：
- 情绪命中：happy → 开心 / 好耶；shy → 脸红；hurt → 委屈；annoyed → 哼；surprised → 问号
- 场景命中：交付完成、晚安、早安、被喂食、长时间没说话
- 未命中就**不发**，不要硬凑（meme 的 matched:false 就是干这个的）

**素材来源（三选一或混用）**：
- ① `TreapGoGo/deepseek-whale-girl` 的 40 张 meme-01..40.webp（社区素材，逐张署名）
- ② `FeWOO/DeepSeek-meme` 的 assets/default（10 张：收到 / 谢谢 / 我在这 / 干得好 / 晚安 / 早安 / 奶茶 / 嗯？/ 哼 / 困）
- ③ 用现有 `assets/whale` 的 expr 图集切帧当「表情贴纸」，零新素材先把链路跑通

**验收**：说「这版写得不错啊」→ 命中「谢谢 / 得意」；说「晚安」→ 命中「晚安」；连发 10 轮贴纸 ≤3 张；面板手动发成功；catalog 里每个 id 都能渲染。

### P0-3 动作状态分层（解决「临时表情回不去」）

**现状问题**：`js/whale-render.js` 只有 `play(clip,{priority})` / `pose(name,{priority})`，优先级一乱就卡在某个姿势；道具 / 特效 / 一次性动作没有生命周期。

**做法**（照 `Andersen216:assets/pet.js:96-546` 的三层模型）：
- `base`：由情绪决定（MOODS → POSES），永久有效
- `override`：一次性动作 / 表情，带 TTL（3~4s），到期回 base
- `props`：常驻装饰（饭碗、眼镜、贴纸），同 group 互斥，needs 自动补前置
- `gaze`：视线跟随鼠标（可开关）
- **单写者原则**：同一时刻同一参数只有一个来源，冲突记 skipped 日志，方便排查
- **2 秒看门狗**：状态机 2s 没更新就复位到 base（防「卡脸」）
- **待机权重表**：`IDLE_TABLE = [glance 46, express 28, mutter 22, hungry 4, 无奈 2]`，3.5~7.5s 抽一次；连续 120s 无互动 → 打哈欠 → 睡
- **防抖**（照 musume）：状态信号消抖 300ms，信号消失后保持 4s 再回落

**验收**：连续切 10 次情绪无卡住；发呆 3 分钟自动睡、点一下能醒；临时动作结束后一定回当前情绪表情。

## 3. P1：把「她真的记得你、看得见你在干什么」补上（3~5 天）

### P1-1 记忆四区 + 注入（收益最大）

**现状**：`chat.slice(-8)`，前 4 轮说过什么就忘了；`whale.mem.v1` 只服务离线兜底台词。

**做法**（照 `wxzjss/dsh-whale-loli:src/memory.js` 717 行的结构，本地简化）：
- 四区：**固定记忆**（8 小节，永久，如「用户叫阿伟」「在做 live2d-companion 项目」）+ **滚动摘要**（每轮一条，80 条 FIFO）+ **最近详细**（5 条原文）+ **归档索引**（旧摘要的标题链）
- 上限 `maxChars 16000`，超了按顺序丢：最旧摘要 → 详细区 → 固定记忆
- 注入：在 system prompt **固定位置**插 `## 你记得的事` 段（别插最前，会毁掉前缀缓存）
- 写入：每轮结束后**异步**用一次便宜的非流式调用产出 1 行摘要（`{"mem":"..."}`），失败静默；也可先用纯规则（正则抽人名 / 项目 / 偏好）跑通再换模型
- 存储：localStorage（复用现有 key）+ 导出 / 导入；导出格式可借 musume 的 portable 方案：`{schema, version, data}` + 16 字段白名单 + 校验码，换机器能带走

**验收**：告诉它「我叫阿伟」→ 关页面重开 → 问「我叫什么」能答；问 10 轮前的项目名能答；localStorage 里能看到四区结构；导出文件能在另一台机器导入。

### P1-2 工作状态联动（让动作跟着你干活变）

**现状**：她不知道你在 DSH 里干什么，永远在待机。

**做法**：
- **读会话**：`%USERPROFILE%/.dsh/sessions/**/session.v4.jsonl.zstd`，用 seek + get_frame_size 只解完整帧、offset 只推进到最后一个完整帧（dafeiyu 实测 452ms → 0.09ms/拍），轮询 700ms；切会话那一拍不反应
- **状态映射**（照 `桌宠.py:4073` 的 DSH_ACTS / DSH_TOOL_KIND + 优先级链 `approval > error > start > done > tool_* > working > sing > idle`）：
  read / glob / grep → 翻书看图纸；pwsh → 敲键盘；edit / write → 写字；web_* → 看手机；ask → 头顶问号；报错 → 炸毛；收工 → 好耶
- 触发判据用「工具调用计数增加 + 1.2s 冷却」，别用时间去抖
- 备选实现（如果不想解析 zstd）：musume 的 `TOOL_POSES` 是**刮宿主 DOM** 的工具卡文本、indexOf 匹配 deploy / test / debug / search / write / bash / review / plan，8 条表；本地若做成 DSH 页面内嵌，这条路更省事
- **形态**：先做成网页里一个开关（`?dsh=1` 或按钮），不注册插件、不改 DSH 配置；读不到就静默回到纯聊天

**验收**：在 DSH 里跑一次改代码，动作依次 敲键盘 → 写字 → 好耶；报错时炸毛；关掉开关完全不受影响。

### P1-3 气泡调度（她现在会抢话）

**现状**：待机台词、情绪反应、你的回复共用一个气泡，偶发自言自语盖掉正式回复。

**做法**（照 `桌宠.py:7996` 的 say() 调度 + musume 的节流）：
- 队列 + 优先级：对话回复 > 互动反应 > 待机闲话；闲话永远不能盖掉未读完的回复
- 去重（最近 5 条不重复）、队列上限 6 条（超了丢最旧）
- **节流**：工作态两档冷却窗（话痨 15–40s / 安静 90–240s），窗口内只说一句；空闲闲聊 5–8 分钟一次；23:00–5:59 静默
- 每条台词绑定气泡时长（`say(text, seconds)`），不要统一 5.2s

## 4. P2：好玩但可以以后做（每项 0.5~2 天）

- **P2-1 成就 + 小游戏**：照 musume 的轻量骨架——静态表 `{id, icon(emoji), name, desc}` + 存档里的 id 数组 + 5 个纯函数判定 + 解锁统一 announceUnlocks（换立绘 3.5s + 🏅 粒子 + 气泡 + 写日记）。本地只做 **12 项轻成就**（第一次对话 / 喂鱼 10 次 / 连续 3 天 / 被夸 20 次 / 深夜陪伴…）+ **1 个小游戏**（喂食节奏）；小游戏写成 DOM-free 纯函数状态机，每天限 3 局。

## 6. 人设/设定专章（在现有基础上补 5 处）

### 6.1 位置即约束：硬规矩挪到 system prompt 最末尾
`Weidows/dsh-whalechan-herself` 的 persona 分 prefix / suffix 两段：性格放前面，**硬规矩放最后**。README 结论很直白：只写 prefix，聊几十轮口气就飘回客服腔。
→ 本地把「一次一到两句」「不写旁白」「不发贴纸就闭嘴」这类**可判定硬规则**移到 system-prompt.md 最后一段。

### 6.2 AI 味黑名单（照 whale-loli「出现即失败」）
清单：首先 / 其次 / 综上所述、希望这个回答对你有帮助、作为 AI、这是个好问题、Markdown 标题加粗、「保证 / 绝对有效」。
→ 加进 `persona.json` 的 `speech.taboos`，并在 P0-1 的代码侧做**命中告警**（开发时 console.warn，上线静默）。

### 6.3 情绪互斥表（照 Neko3000 的 expression-presets.json）
17 个表情各带 face_cues / forbidden_cues（例：惊慌时禁止「放松微笑」「螺旋瞳孔」）。
→ 本地给 MOODS 的参数增量加互斥断言：切到 angry 必须清掉 shy 的腮红增量，反之亦然——P0-3 的分层模型正是为这个准备的。

### 6.4 合规与署名（照 xiaoweigen/deepseek-dafeiyu-assets 的 7 行出处表）
格式：原作者 / 二创 / 整理 / 来源 / 前序修改 / AI 辅助 / 许可。
→ 本地 `CREDITS.md` 现在是散文，改成这张表；贴纸若用社区图，逐张记 author + source + license（TreapGoGo 的 manifest 就有 author / source / issueUrl 字段可抄）。

### 6.5 设定分层：永久身份 / 可覆盖字段
Neko3000 的 character-spec.md 把 prompt 拆成「永久身份」（鲸鳍耳、呆毛、鲸尾、深海蓝→青发尾）+「可覆盖字段」（style / costume / background，各带 `mode: canonical | custom`）。
→ 本地 persona.json 的 appearance 拆成 @identity@（不可变）+ @skin@（可换：服装 / 场景），以后换皮肤不污染人设。
